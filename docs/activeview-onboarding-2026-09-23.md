## Как устроена работа с AV (по словам Julia)
1. **Два инструмента:**
   - **Godi Studio** (CMS, «работает как WordPress») — здесь мы **сами создаём статьи и воронки**; доступ выдаётся по форме с e-mail'ами после звонка, там есть обучающее видео. Созданный контент появляется в дашборде AV.
   - **Дашборд app.activeview.io** — метрики, инвентарь, стратегия. API-ключ и инструкции для девов там же.
2. **Revenue:** gross = всё из GAM; net = после **ручных** вычетов, которые мы сами вводим в Settings → Company → Fixed cost setup: **MCM revshare 10%** (по контракту), налоги, банковские комиссии, % байеру и т.п. ROI появляется после подключения Meta/Google аккаунтов (вычитаются затраты на трафик).
3. **Компоненты дашборда:** Rankings (лучшие URL/сайты по выручке), Access management (3 типа профилей + кастомный доступ по фичам/сайтам), Websites list (обзор сайтов, статус pricing rule), Compliance Manual (ручная проверка командой AV с замечаниями по URL) и Compliance Bot (быстрая AI-проверка новой страницы по запросу).
4. **Redirect** — «защита кампаний»: в Meta ставим final URL = `redirect.<домен>/<path>`, а в дашборде потом **меняем/добавляем целевые URL и веса без перезапуска объявления** (learning phase сохраняется). Режимы: ручной сплит (50/50, 33/33/33), **dynamic distribution** — алгоритм ~7 дней смотрит RPS (revenue per session) и сам перекидывает трафик на лучший URL. Кейсы: A/B, прогрев нескольких страниц одной ниши, старт с одним сегментом и добавление позже. Лимита на число редиректов нет.
5. **Chat Builder** — прелендер-чат с монетизацией до статьи: реклама показывается между репликами (1–5 контент-юнитов + top до/после первого взаимодействия), два режима: скриптовые варианты ответов с CTA на статью, либо **AI-агент** (companion и др.) без статьи вообще; есть **lead capture** (ключ + вопрос → webhook) для ретеншена. Лучше всего для dating (люди хотят «поговорить»), для jobs лучше статья + CTA.
6. **Ad Inventory** — управляем блоками сами без техподдержки AV: юниты создаются в GAM при имплементации и отражаются в скрипте; **rebid** = если основной блок не продался, вторая попытка по меньшей цене; можно удалять/создавать блоки (offerwall, rewarded…), таргетить по стране/source key, менять копию; A/B через Redirect (URL с offerwall vs без).
7. **Пиксель Meta:** пиксель остаётся в нашем Meta-аккаунте; **после подключения аккаунта в Campaign Analysis появляется опция «manage conversions»** (настройка событий/триггеров) — детали покажут после подключения.
8. **Campaign Analysis:** revenue/cost/ROI по кампаниям, трендовые индикаторы (красный, если ROI ниже порога, напр. 20%), **автоправила** (бюджет ±/фиксированный/в %, desired CPA), детали кампании с **вкладом каждого ad-юнита** и креативами, сохраняемые виды. Автоподбор набора юнитов по нише/гео — нет, Julia передаст идею техкоманде.
9. **Pricing Rules** — обсуждение на **втором звонке через ~2 недели**, когда будут данные и подключены аккаунты.

## Договорённости / следующие шаги
1. Julia присылает формы → указываем e-mail'ы → получаем доступ в **Godi Studio**.
2. Создаём статьи в Godi Studio → они появляются в дашборде → проходят approve.
3. Параллельно **подключаем Meta-аккаунты** в Campaign Analysis (после подключения обязательно **выставить UTM-параметры в кампаниях**, иначе AV не свяжет данные).
4. Настраиваем ad-блоки; при желании чат → статья или только AI-чат.
5. Создаём Redirect на статью/чат, ставим URL в Facebook, запускаем; смотрим отчёты.
6. **Перед первыми запусками шлём каждый URL в Slack** → тикет → Julia проверяет URL и стратегию (ниша, гео, пиксель, ML) → approve → первый тест → фидбек.
7. **Ниши:** не смешивать много ниш на одном домене (compliance, Google не понимает ценность) — идеально 1–2 ниши на домен; **после результатов AV выделит ещё 1–2 домена**. Julia пришлёт список ниш/гео, которые лучше всего идут у них (мы просили: jobs, dating).
8. Второй звонок через ~2 недели: pricing rules с подключёнными аккаунтами; начинать можно раньше.
