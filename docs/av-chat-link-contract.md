# AV chat — запуски на AI-чат ActiveView (Chat Builder)

Как рельса **AV** ведёт рекламу не на статью, а на **чат** ActiveView, что именно лаунчер
проверяет перед запуском и что нужно сделать на стороне ActiveView, чтобы чат стал запускаемым.

Коротко: чат — третий вид назначения рядом со статьёй и Redirect-путём. В карточке это вкладка
**AI chat** поля *Destination*: байер вставляет адрес чата, сервер проверяет **хост** (активирован
ли он и показывает ли рекламу) и сохраняет адрес в каноническом виде. Ссылка в объявлении несёт
тот же трекинг-хвост, что и для статьи.

## Ссылка

```
https://chat.<сайт>/?asst=<id чата>&utm_source=facebook&utm_medium={{campaign.id}}&utm_campaign=<avNNN>&utm_term={{adset.id}}&utm_content={{ad.id}}
```

- `<id чата>` — 24 hex-символа (`6a2312cef9f4e11b130fc523`), берётся в ActiveView → Chat Builder
  → *View your chat*.
- Каноническая форма адреса — **`/?asst=<id>`**. Дашборд ActiveView выдаёт путевую форму
  `https://chat.<сайт>/<id>/` — её тоже можно вставлять, лаунчер приводит к канонической.
  Причина: форма `?asst=` отвечает на всех чат-хостах ActiveView, путевая — только там, где под
  неё настроен шлюз (проверено 29.09 на ~139 чат-хостах других паблишеров).
- Трекинг-хвост присоединяется через `&` (у адреса чата уже есть query); макросы Facebook
  остаются буквальными. Рекламный скрипт чата читает `utm_*` из URL в GAM key-values так же, как
  скрипт статьи.

## Что проверяет лаунчер (и чего проверить нельзя)

Запуск, клон и кнопка **Check** в карточке проходят одну и ту же проверку
(`lib/av-destination.ts` → `lib/av-chat.ts`). Отказ = ничего не создано, ключ `avNNN` не потрачен.

| Проверка | Отказ | Чей ход |
|----------|-------|---------|
| Хост — поддомен нашего AV-сайта (сайты берутся из `GET /me`) | `destination_not_av` | байер: неверный адрес |
| CNAME хоста указывает на чат-шлюз ActiveView | `destination_not_av` | — |
| Шлюз маршрутизирует хост, у хоста свой сертификат | `chat_not_live` | завершить активацию в Chat Builder |
| В настройках хоста (`/worker.js`) есть ключ чата | `chat_not_live` | опубликовать чат в Chat Builder |
| Назван рекламный скрипт, и это не заглушка шаблона | `chat_not_monetized` | ActiveView: включить рекламу |
| Реклама не выключена в настройках, настройки полные | `chat_not_monetized` | Chat Builder / ActiveView |
| Рекламный скрипт реально отдаётся CDN ActiveView | `chat_not_monetized` | ActiveView: опубликовать скрипт |
| Адрес чата отвечает 200 (редиректы не принимаются) | `chat_not_live` | — |
| Любая из проверок не смогла выполниться (DNS, сеть, CDN) | `destination_check_failed` (502) | повторить позже |

**Зачем проверка рекламы.** ActiveView включает рекламу на новом чат-хосте вручную, после своей
проверки; до этого чат в статусе *Pending monetization* и трафик на него ничего не зарабатывает.
На живых чат-хостах встречаются все три состояния: скрипт не назначен, стоит заглушка шаблона
(`localhost`), скрипт назван, но файла на CDN нет. Во всех трёх чат открывается, а рекламы в нём
нет — поэтому запуск отклоняется.

**Чего проверить нельзя — существование самого чата.** Шлюз ActiveView отдаёт одну статичную
страницу-оболочку, поэтому *любой* id правильного формата отвечает 200. Лаунчер проверяет формат
id и готовность хоста; сам id — ответственность байера. После сохранения откройте чат кнопкой
**Open** в карточке и убедитесь, что это он.

## Что нужно сделать в ActiveView (один раз на сайт)

1. **Chat Builder → Let's build**: выбрать корневой домен и поддомен (`chat`). Поддомен
   закрепляется навсегда.
2. Добавить в DNS одну запись `CNAME chat → assistant-quiz-infrastructure-gateway.activeview.app`
   и нажать **Yes, validate DNS** (шаг необратим). Дальше ActiveView сам выпускает сертификат и
   поднимает сервер.
3. Указать компанию и ссылки Terms / Privacy (требование Google), имя чата, имена и фото агента.
4. Собрать поток: минимум три блока *Message / Question / CTA* и в конце **AI Agent** (агент
   выбирается из каталога ActiveView — своего промпта нет) либо CTA на статью.
5. Написать AdOps ActiveView: попросить включить рекламу на чат-хосте и согласовать URL. Пока они
   этого не сделали, вкладка **AI chat** показывает хост как *not ready* с причиной.

На одном поддомене может жить сколько угодно чатов — они различаются только `asst`.

## Вопросы к ActiveView, от которых зависит отчётность

- Ключи **UTM Campaign Values** (`av001…`) привязаны к сайту и автоматически отключаются, если по
  ним 7 дней нет рекламных запросов (включить обратно может только AdOps). Действуют ли ключи,
  зарегистрированные на `thecadrion.com`, на чат-поддомене — или их нужно регистрировать отдельно?
- В отчётах ActiveView чат виден как отдельный поддомен. Появится ли он в `GET /me` и в
  `/report/kvp` внешнего API — без этого выручку чата лаунчер по API не прочитает.
- В части чатов ActiveView включает rewarded-гейт на вход (*offerWall*); для трафика из Meta он
  незакрываемый. Нужен ли он нам — решить до первого запуска.

## Настройки окружения (все необязательные)

| Переменная | Что делает |
|------------|------------|
| `AV_CHAT_GATEWAYS` | Хосты чат-шлюза через запятую. **Заменяет** встроенный — на случай, если ActiveView сменит шлюз. |
| `AV_CHAT_SCRIPT_CDN` | https-origin, с которого берётся рекламный скрипт чата. **Заменяет** `https://scr.actview.net`. |

## Проверка

```
node --test tests/av-chat.test.ts tests/av-destination.test.ts tests/av-link.test.ts
```

DNS и все запросы в тестах подменены; формы `worker.js` в тестах — те, что реально отдают
чат-хосты ActiveView (настроенный хост, неопубликованный шаблон, неполные настройки).
