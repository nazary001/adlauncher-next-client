## Cross-cutting rules

- **Pool max is dynamic for AV**: `GET /api/av/keys` answers `{ ok, used: string[], next, poolMax: <registered>, registered, codecMax: 999 }`. The launcher board must treat `poolMax` from the preview endpoint as the effective max for EVERY pool (fallback `pool.max` when the endpoint omits it): `poolFree = max − |used ∩ pool codes ≤ max|`, `assignPoolCodes(rows, reserved, {...pool, max})`. `poolMax === 0` (AV not registered) must read as "No AV keys are registered in ActiveView yet — owner: AV keys page", never as "pool exhausted".
- **AV delivery**: objective `OUTCOME_TRAFFIC` (locked field "Traffic"), optimization `clicks` (locked "Link clicks"), pixel none (locked "No pixel — link clicks"), conversion event hidden, bid strategies = every strategy except min-ROAS (`bidKind(...) !== "roas"`).
- **AV destination** = `Campaign.landing` holds the bare destination URL (article or redirect path). `Campaign.gcm` holds the AV key. Link = `fullLandingUrl(partner, c.landing, c.gcm, false)`.
- **Dormancy**: every `/api/av/*` route: session check (401) → `if (!avRailEnabled()) return 404 {ok:false, error:"av_rail_disabled"}` → the rest. Pages under `app/(app)/av/**` redirect to `/` when `NEXT_PUBLIC_AV_ENABLED !== "1"`.
- **No LION anywhere** for AV. No `reportPagesUsed` fill badges (AV fanpages pass `volume: null` to useFanpages).
- **Turbopack const-fold gotcha**: never write a thin async wrapper `async function f(x){ return impl(x) }` around a nullable result — keep full bodies.
- Match the surrounding code's comment density and idiom (long explanatory comments, owner-dated notes). Keep MO/AIF/HS behaviour byte-identical.
