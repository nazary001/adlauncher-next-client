# Snapchat clone link — контракт для внешнего инструмента

Инструкция для разработчика внешнего инструмента (статистика / дашборд / hs-tools): как кнопка
**Clone** должна передавать **Snapchat**-кампании в наш Snapchat-клонер (Ad Launcher, борд
`/snap/clone`).

Коротко: **передаём только ID кампаний-источников или их партнёрские ключи `glo-snp_NNN`**. Всё
остальное (аккаунт, ad squad, бюджет, ставку, гео, возраст, устройства, тексты, лендинг и сами
креативы) клонер сам читает из Snapchat Marketing API. Байер на борде выбирает аккаунт назначения,
число копий, бюджет и ставку (при желании и всё остальное) и жмёт **Clone**. Копии строит наш
сервер через Snapchat API, на наш же аккаунт, и каждая копия получает **свой новый ключ**.

Это Snapchat-аналог `google-clone-link-contract.md` и FB-контрактов `clone-link-contract.md` /
`juro-link-contract.md`. Формат тот же; отличия перечислены в разделе «Чем отличается от
Google- и FB-ссылок».

## Ссылка

```
https://adlauncher.gcamazingtool.xyz/snap/clone?ids=<campaignId1>,<campaignId2>,...
```

или по партнёрским ключам (по ключу берётся кампания, которая держит его сейчас):

```
https://adlauncher.gcamazingtool.xyz/snap/clone?keys=glo-snp_012,glo-snp_045,...
```

Оба параметра можно передавать вместе: `?ids=…&keys=…`.

Локально (dev): `http://localhost:3000/snap/clone?ids=...`. В dev нужен
`NEXT_PUBLIC_SNAP_ENABLED=1` в `.env.local`, иначе `/snap/clone` уводит на `/`.

## Параметры

| Параметр | Обяз. | Что это |
|----------|-------|---------|
| `ids`    | один из двух | **Snapchat campaign ID** кампаний-источников. Это UUID, например `cf459275-d6aa-48a2-bd91-26ad85d10750`. Тот же ID, что в Snapchat Ads Manager, в нашем дровере «Snap tasks» (`cmp …`) и в Snap Marketing API. Через запятую. |
| `keys`   | один из двух | **Партнёрский ключ** кампании: `glo-snp_001` … `glo-snp_500`. Это `utm_campaign` из отчёта LION `snapchat-report` и ключ из имени кампании `… - glo-snp_012 - …`. Клонер по реестру ключей находит кампанию, которая держит ключ **сейчас**. |
| `mode`   | нет | Не нужен. Режим у Snapchat-клонера один; любое значение игнорируется. |
| `partner` | нет | Не нужен. Snapchat — это не партнёр, а отдельная платформа на нашем аккаунте. |

Правила разбора — одни для обоих параметров:

- регистр не важен, ID и ключи приводятся к нижнему регистру;
- разделители: запятая, пробел, точка с запятой, перевод строки;
- параметр можно повторять (`?ids=a&ids=b`), значения склеиваются;
- в любом параметре можно смешивать ID и ключи, тип определяется по виду значения;
- дубли и любой мусор (не-UUID, ключ вне пула `001…500`) отбрасываются **молча**;
- порядок сохраняется. Берутся **первые 30** источников, остальные молча отсекаются, поэтому режьте
  на своей стороне с предупреждением.

**Больше ничего передавать не нужно.** Никаких бюджетов, аккаунтов, гео, ставок или имён: клонер
прочтёт всё сам из Snapchat.

## Откуда брать ID и ключи

- **Ключ** — самое удобное, если ваш отчёт построен на LION. В
  `GET https://lion.highstakes.tech/api/high-adx-cluster-utms/snapchat-report/?date=…` у каждой строки
  есть `utm_campaign`. Это и есть ключ `glo-snp_NNN`. Клонер сам найдёт по нему кампанию.
- **ID кампании** — если у вас есть сами кампании Snapchat: из Snap Marketing API
  (`GET /v1/adaccounts/{id}/campaigns` → `campaign.id`), из адреса кампании в Ads Manager или из
  нашего дровера «Snap tasks» (кнопка `cmp …` копирует ID).

Ключ надёжнее, пока кампания жива. Если ключ освободили и снова заняли, он указывает на **новую**
кампанию (так и задумано: ключ = текущий держатель). Чтобы клонировать именно конкретную кампанию,
передавайте её `ids`.

## Как открывать

Обычный GET-переход. Рекомендуется новая вкладка, чтобы ваш инструмент не закрывался:

```html
<!-- одна строка отчёта по ключу -->
<a href="https://adlauncher.gcamazingtool.xyz/snap/clone?keys=glo-snp_012"
   target="_blank" rel="noopener">Clone</a>

<!-- одна строка по ID кампании Snapchat -->
<a href="https://adlauncher.gcamazingtool.xyz/snap/clone?ids=cf459275-d6aa-48a2-bd91-26ad85d10750"
   target="_blank" rel="noopener">Clone</a>
```

```js
// массовый Clone по выбранным строкам: ключи glo-snp_NNN и/или ID кампаний Snapchat
const CAP = 30; // столько источников принимает борд за раз
const BASE = "https://adlauncher.gcamazingtool.xyz/snap/clone";
const UUID = /^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/;
const KEY = /^glo-snp_(\d{3})$/;

function openSnapCloner(refs) {
  const clean = [...new Set(refs.map((s) => String(s).trim().toLowerCase()))].filter(
    (s) => UUID.test(s) || (KEY.test(s) && +s.slice(-3) >= 1 && +s.slice(-3) <= 500),
  );
  if (!clean.length) { alert("No Snapchat campaigns selected"); return; }
  let take = clean;
  if (clean.length > CAP) {
    if (!confirm(`Selected ${clean.length} campaigns, but the cloner takes ${CAP} at a time. Open the first ${CAP}?`)) return;
    take = clean.slice(0, CAP);
  }
  const ids = take.filter((s) => UUID.test(s));
  const keys = take.filter((s) => KEY.test(s));
  const q = [ids.length ? `ids=${encodeURIComponent(ids.join(","))}` : "", keys.length ? `keys=${encodeURIComponent(keys.join(","))}` : ""].filter(Boolean).join("&");
  window.open(`${BASE}?${q}`, "_blank", "noopener");
}
```

## Примеры

```
# одна кампания по ключу
/snap/clone?keys=glo-snp_250

# одна кампания по ID
/snap/clone?ids=cf459275-d6aa-48a2-bd91-26ad85d10750

# несколько ключей
/snap/clone?keys=glo-snp_012,glo-snp_045,glo-snp_250

# смешанно: ID и ключи (порядок строк на борде = порядок в ссылке, сначала ids, потом keys)
/snap/clone?ids=cf459275-d6aa-48a2-bd91-26ad85d10750&keys=glo-snp_012
```

## Чем отличается от Google- и FB-ссылок

| | FB (`/clone`) | Google (`/google/clone`) | **Snapchat (`/snap/clone`)** |
|---|---|---|---|
| Что передаётся | FB campaign ID | Google Ads campaign ID (11 цифр) | **Snapchat campaign ID (UUID)** или **ключ `glo-snp_NNN`** |
| Параметры | `ids`, `partner`, `mode` (только `br`) | `ids`, `mode` | **`ids` и/или `keys`**; `mode` и `partner` не нужны |
| Кто строит копии | Graph API (MO/AIF) или LION (HS) | LION google-weapon | **наш сервер напрямую через Snapchat Marketing API** |
| Куда | профиль/аккаунт байера | `GLO-HS-001…010` / аккаунт источника (JURO) | **аккаунт источника** (по умолчанию) или любой наш `GC-HS-snapchat-LA-1…10` |
| Ключ копии | — | — | **новый свободный ключ на каждую копию**; ключ источника остаётся у источника |
| Статус копии | PAUSED | ENABLED (строит LION) | рождается PAUSED, включается, когда созданы объявления; есть галочка «Start paused» |

Отдельного JURO у Snapchat нет: перезапуск на том же аккаунте с другим гео — это обычный клон с
изменённым гео в «All settings».

## Важные нюансы

- **Авторизация.** Клонер за логином (тот же аккаунт, что и весь Ad Launcher). Байер должен быть
  **уже залогинен** на `adlauncher.gcamazingtool.xyz`. Сессия продлевается при работе, до 30 дней
  от входа. Если сессии нет, его отправит на `/login`, и параметры ссылки при этом **теряются**:
  после входа откроется главная, ссылку нужно нажать ещё раз. Сохранение через `?next=` пока не
  сделано, как и у FB/Google-ссылок.
- **ID — это кампания.** Передавайте ID кампании, а не ad squad, объявления, креатива или
  аккаунта. Несуществующий ID пройдёт проверку формата, но строка на борде покажет «No such campaign
  on Snapchat — check the id». Кампания, удалённая в Ads Manager, покажет «This campaign is gone from
  Snapchat (deleted in Ads Manager)». Свободный ключ покажет «glo-snp_NNN is free — no campaign holds
  this key». Такие строки не запускаются, остальные работают.
- **Клонируются кампании нашей организации** (аккаунты `GC-HS-snapchat-LA-*`): у токена клонера нет
  доступа к чужим кабинетам.
- **Отклонённые объявления не едут по умолчанию.** Объявления, которые модерация Snap отклонила
  (`REJECTED`), и объявления, поставленные в источнике на паузу, на борде выключены. Повторная
  отправка отклонённого креатива — ещё один страйк всей организации. Байер может включить их вручную.
- **Креативы.** На аккаунте источника медиа переиспользуются как есть. На другой аккаунт файл
  копируется из Snapchat, и тогда каждый файл должен быть не больше **32 МБ**: крупнее борд не даст
  выбрать. Свои креативы через клонер не загружаются, для этого есть обычный запуск `/snap`.
- **Что копируется 1:1:** цель (Pixel purchase / Landing page view), ставка (Auto / Max bid / Target
  cost), дневной бюджет, страны, минимальный возраст, устройства, objective (Awareness & Engagement /
  Sales), заголовок, бренд, CTA, Public Profile, лендинг (без query: `utm_source=stone` и **новый**
  ключ дописываются заново), хвост имени.
- **Чего клон не переносит** (борд пишет об этом жёлтой заметкой на строке): цели и ставки вне
  словаря лаунчера (например, SWIPES, MIN_ROAS; ставится дефолт лаунчера), lifetime-бюджет (будет
  дневной $10), регионы/города внутри стран, верхний возраст, пол, языки, интересы и аудитории,
  детали устройств. Из кампании с несколькими ad squad'ами копируется тот, где больше объявлений.
- **Лимиты.** До **30** источников на борде; **1–20** копий на источник; не больше **45** кампаний за
  одну волну; копий не может быть больше, чем свободных ключей в пуле. Борд не даст нажать Clone при
  превышении.
- **Объём URL.** 30 ID (по 36 символов) — это ~1,1 КБ, проходит спокойно.

## Что происходит на нашей стороне (для понимания)

1. `/snap/clone` разбирает `ids` / `keys`; каждый источник — отдельная панель на борде. Сервер
   (`POST /api/snap/sources`) переводит ключи в кампании по реестру ключей и читает каждую кампанию
   из Snapchat: кампанию, ad squad, объявления, креативы, медиа и вердикт модерации. Только чтение.
2. Из источника собирается черновик клона: те же настройки, лендинг без query, хвост имени
   источника. Всё, что лаунчер перенести не может, видно в заметке на панели.
3. Байер настраивает волну: аккаунт назначения (по умолчанию свой аккаунт источника), число копий,
   бюджет, ставку, цель, выбор креативов; в «All settings» — objective, тексты, гео, возраст,
   устройства, лендинг, Public Profile.
4. **Preview → Clone** отправляет одну волну на наш сервер (тот же конвейер, что и обычный запуск
   `/snap`), и вкладку можно закрывать. Для каждой копии сервер берёт новый ключ, создаёт кампанию
   (PAUSED), ad squad, креативы и объявления (медиа источника на его аккаунте, копия файла на
   другом), затем включает кампанию.
5. Имя копии: `[DD.MM] (SNP) <ниша> - <GEO> - <новый ключ> - <байер> - GC-Launcher[ - <хвост>] - CLONE_FROM=<ключ источника>`.
   Если у источника нет нашего ключа, после `CLONE_FROM=` стоят первые 8 символов его ID. В реестре
   ключей копия хранит `clone_of = <ID кампании-источника>`.
6. Прогресс виден в дровере **Snap tasks** (кнопка в шапке на Snapchat-страницах): строки `snc-…` с
   тегом `clone · …`. Там же и на странице `/snap/keys` у каждой собранной кампании есть кнопка
   **Clone**: это та же ссылка этого контракта.

## Если кнопка живёт в hs-tools

Разметка такая же, как у FB/Google-кнопок (`clone-link-contract.md`, `google-clone-link-contract.md`):
`.row-select` + ID в data-атрибуте строки.

1. Если строки Snapchat-отчёта построены на LION `snapchat-report`, у строки есть `utm_campaign`,
   то есть ключ. Кладите его в data-атрибут и открывайте `…/snap/clone?keys=…`.
2. Если строки — это кампании Snapchat из Marketing API, кладите `campaign.id` и открывайте
   `…/snap/clone?ids=…`.
3. Массовая кнопка: собрать `.row-select:checked` → значения → `openSnapCloner(refs)` из раздела
   «Как открывать» (дедуп, фильтр формата, кап 30 с confirm, новая вкладка).
4. Кнопка на строке — обычный `<a target="_blank" rel="noopener">` с одним ключом или ID.

Ничего на стороне Ad Launcher менять не нужно.
