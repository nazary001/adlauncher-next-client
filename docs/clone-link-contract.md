# Clone link — контракт для внешнего инструмента (статистика)

Инструкция для разработчика статистики: как кнопка **Clone** должна передавать кампании
в наш дубликатор (Ad Launcher). Коротко: **передаём только ID кампаний**, всё остальное
(бюджет, гео, ставку, креативы, имена) лаунчер сам подтягивает из Facebook по этим ID.

## Ссылка

Кнопка «Clone» открывает наш роут `/clone` с параметрами:

```
https://adlauncher.gcamazingtool.xyz/clone?partner=in&ids=<campaignId1>,<campaignId2>,...
```

Локально (dev): `http://localhost:3000/clone?partner=in&ids=...`

## Параметры

| Параметр  | Обяз. | Что это |
|-----------|-------|---------|
| `ids`     | да    | Facebook **campaign ID** (числовые ID кампаний — те же, что в Ads Manager / в Graph API / в вашей статистике), через запятую. Порядок сохраняется, дубли игнорируются. |
| `partner` | нет   | Партнёр. Сейчас поддерживается только `in` (Индусы). Если не передать — по умолчанию `in`. |

**Больше ничего передавать не нужно.** Никаких бюджетов, гео, креативов или имён — лаунчер
получит их сам из FB по ID (у Индусов кампании живут на одном аккаунте
`GC-Magicoffers-BR-1500`, поэтому аккаунт указывать тоже не надо).

## Как открывать

Обычный GET-переход. Рекомендуется новая вкладка, чтобы статистика не закрывалась:

```html
<!-- один клик по строке кампании -->
<a href="https://adlauncher.gcamazingtool.xyz/clone?partner=in&ids=120210000000101"
   target="_blank" rel="noopener">Clone</a>
```

```js
// массовый клон выбранных строк
const ids = selected.map(c => c.campaignId).join(",");
const url = `https://adlauncher.gcamazingtool.xyz/clone?partner=in&ids=${encodeURIComponent(ids)}`;
window.open(url, "_blank", "noopener");
```

## Примеры

```
# одна кампания
/clone?partner=in&ids=120210000000101

# несколько
/clone?partner=in&ids=120210000000101,120210000000102,120210000000103
```

## Важные нюансы

- **Авторизация.** Дубликатор за логином (тот же аккаунт Amazon Tools). Байер должен быть
  залогинен в `adlauncher.gcamazingtool.xyz`. Если сессии нет — его отправит на `/login`.
  > ⚠️ Phase 2: сейчас при редиректе на логин параметры `ids` теряются. Мы добавим их
  > сохранение через `?next=`, чтобы после входа возвращало на дубликатор с теми же ID.
  > Пока — просто убедитесь, что байер уже залогинен.
- **Объём.** ID в URL — компактно, десятки кампаний проходят спокойно. Если понадобится
  передавать сотни за раз — скажите, переключимся на POST-передачу с токеном.
- **ID — это кампания, не адсет/объявление.** Передавайте именно `campaign_id`.

## Что происходит на нашей стороне (для понимания)

1. `/clone` читает `ids` и тянет по каждому из FB: кампанию → адсет(ы) (бюджет, bid/ROAS,
   таргетинг, пиксель) → объявления (креативы, `video_id`).
2. Показывает их в таблице; байер правит имя/ROAS/бюджет/таргетинг, задаёт число копий.
3. По кнопке **Duplicate** создаёт N копий (видео переиспользуются по `video_id`, без
   перезаливки), PAUSED, через существующий launch-пайплайн.

> Статус: **готово end-to-end** — и fetch из FB (`/api/clone/sources`), и создание дублей
> (`/api/clone/run`, всё создаётся PAUSED) работают и проверены вживую. Формат ссылки из этого
> документа — финальный и не изменится.
